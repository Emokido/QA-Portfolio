# TF-BUG-009 — 홈페이지 검색 버튼을 눌러도 검색 결과가 표시되지 않음

- 결함 상태: `Open`
- 발견 경로: 사용자 수동 프런트 탐색
- 기준 프로젝트: 스프린트 1 Java/Spring 완성본과 Next.js 프런트
- 기준 커밋: `e2431223ce2a18c8f944d544cba76b951ce0356d`
- 영향 기능: 홈페이지 여행 검색 CTA
- 테스트 수준: Browser UI · 정적 코드 상관 분석
- 심각도: `Major`
- 수정 우선순위: 제품 담당자 결정 필요
- 실행 주체: `User`

## 1. 요약

홈페이지의 여행지와 검색어를 입력하고 `검색하기`를 눌러도 화면 이동, 결과 갱신 또는 사용자 안내가 발생하지 않는다. 검색 폼이 핵심 기능처럼 제공되지만 submit 핸들러에는 실제 검색 동작이 구현돼 있지 않다.

## 2. 원본 기록과 추적

- 수동 탐색 원본 번호: `BUG-001`
- 원본 발견 기록: 사용자 내부 자료로 보존하며 공개 산출물은 아래 정제 보고서를 사용한다.
- 수동 탐색 보고서: [TripFriend 수동 프런트 탐색 보고서](../reports/manual-frontend-exploration-report.md)
- 기존 P0·Stage 7 테스트와 직접 중복되지 않으며 누적 P0 집계에 합산하지 않는다.

## 3. 테스트 환경

- Windows 11
- Chrome
- Frontend `localhost:3000`
- Backend `localhost:8080`
- 로그인 및 로그아웃 상태에서 사용자가 관찰

## 4. 재현 절차

1. TripFriend 홈페이지에 접속한다.
2. 여행지를 선택하거나 검색어를 입력한다.
3. `검색하기` 버튼을 누른다.
4. 화면과 URL 변화를 확인한다.

## 5. 기대 결과

입력 조건에 맞는 검색 결과를 표시하거나 검색 결과 페이지로 이동한다. 검색 기능을 제공하지 않는 상태라면 사용자가 이해할 수 있는 안내가 있어야 한다.

## 6. 실제 결과

홈페이지가 그대로 유지되며 사용자에게 결과나 안내가 표시되지 않았다.

## 7. 코드 상관관계

- `frontend/src/app/page.tsx`의 `handleSearch`는 `preventDefault()` 후 검색값을 Console에 출력한다.
- 검색 API 호출, 상태 갱신 또는 Router 이동은 없고 `검색 결과 페이지로 리다이렉트 기능 추가 예정` 주석만 존재한다.

코드는 사용자 관찰을 설명한다. 제품 코드는 변경하지 않았다.

## 8. 영향과 심각도 근거

- 첫 화면의 주요 검색 CTA가 아무 동작도 하지 않아 사용자가 기능을 완료할 수 없다.
- 별도의 동행 모집 목록 진입 경로가 있더라도 현재 CTA 자체의 무응답은 핵심 기능 신뢰도를 저하시킨다.
- 기능 단위가 완전히 동작하지 않으므로 `Major`를 제안한다.

## 9. 수정 후 재검증 조건

- 여행지·키워드가 목적 검색 API 또는 결과 페이지에 전달되는지 확인한다.
- 검색 결과 있음·없음과 빈 입력을 각각 확인한다.
- 버튼 클릭과 Enter 제출 결과가 일치하는지 확인한다.
- 로딩·실패 시 사용자 안내가 표시되는지 확인한다.

## 10. 확인 한계

- Codex가 제품을 재실행하지 않았으며 사용자 제공 실행과 기준 코드만 대조했다.
- 홈페이지 검색이 여행지, 동행 모집 또는 별도 통합 검색 중 무엇을 대상으로 하는지는 명시된 요구사항에서 확정하지 않았다.
