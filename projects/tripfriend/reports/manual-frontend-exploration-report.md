## 1. 목적과 범위

사용자가 TripFriend 프런트를 자유 탐색하면서 발견한 6건을 기존 결함, 요구사항, 기준 코드와 대조해 재현 가능한 결함 기록으로 정제한다. 이번 검토는 사용자가 제공한 설명과 화면 증거를 근거로 하며 Codex가 제품을 다시 실행하지 않았다.

사전에 번호가 부여된 시나리오별 전체 실행 결과와 총 실행 케이스 수는 제공되지 않았다. 따라서 이 문서는 `6 Fail`이라는 테스트 집계를 만들지 않고, **수동 탐색 세션에서 관찰된 6건**을 기록한다. 기존 P0 49개와 Stage 7·Postman 집계에도 중복 합산하지 않는다.

## 3. 검토 결과와 코드 상관관계

### TF-BUG-009 — 홈페이지 검색 동작 미구현

`frontend/src/app/page.tsx`의 `handleSearch`는 submit 기본 동작을 막고 검색값을 Console에 출력할 뿐, 검색 API 호출이나 결과 페이지 이동을 수행하지 않는다. 사용자 관찰과 코드가 일치한다. 화면에서 핵심 검색 기능처럼 제공되므로 기능 미완성을 제품 결함으로 분류한다.

### TF-BUG-010 — 회원가입 CTA 경로 오류

홈페이지 하단 링크는 `/signup`을 가리키지만 실제 회원가입 페이지와 다른 헤더 링크는 `/member/signup`을 사용한다. 사용자가 확인한 `GET /signup 404`와 코드가 일치한다. 다른 진입 경로가 있어 전체 회원가입이 막힌 것은 아니므로 Minor를 제안한다.

### TF-BUG-011 — 초장문 검색 오류 처리

사용자는 공백 포함 11,177자 키워드로 검색했을 때 `모집 글을 불러오는 중 오류가 발생했습니다.`와 fetch 오류를 확인했다. 프런트는 키워드 길이를 제한하지 않고 요청 실패를 일반 오류로 표시한다. 허용 최대 길이는 명시되지 않았으므로 특정 길이를 정답으로 단정하지 않고, 과도한 입력을 통제하지 못해 화면 오류로 전환되는 복원력 문제로 기록한다.

### TF-BUG-012 — 모집 인원 필터의 입력·범위 검증 부재

모집 인원 필드는 `type="number"`만 사용하고 최소값·정수 단위·최소/최대 관계 검증이 없다. 값은 JavaScript `Number`로 변환되지만 백엔드 `/recruits/search3`는 `Optional<Integer>`를 받는다. 사용자가 관찰한 소수 입력 오류, 음수 허용, 최소값이 최대값보다 큰 범위 허용을 같은 입력 경계 결함의 변형으로 묶는다. 정확한 허용 인원과 오류 응답 정책은 명시되지 않아 제품 담당자 확인이 필요하다.

### TF-BUG-013 — 최초 리뷰 조회수 중복 증가

사용자는 조회수 0인 리뷰의 첫 상세 진입에서 2가 증가하고, 이후 동작은 로그인·세션에 따라 달라짐을 관찰했다. 백엔드는 세션의 `VIEWED_REVIEWS`에 처음 추가된 리뷰만 증가시키도록 구현돼 있어 한 세션의 한 상세 요청은 1 증가가 코드상 의도다. 프런트 상세 화면은 마운트 시 상세 API를 호출하며 Next.js 개발환경의 중복 렌더·요청 가능성은 원인 가설일 뿐 확정하지 않는다. Network 요청 수를 포함한 재검증 전까지 환경 제한을 명시한다.

### TF-BUG-014 — 댓글 길이 오류가 일반 메시지로만 표시됨

백엔드 `CommentRequestDto.content`에는 2~100자 검증과 구체적 메시지가 있다. 프런트 `review-detail.tsx`는 공백 여부만 검사한 뒤 요청하며, 실패 응답의 필드 메시지를 표시하지 않고 `댓글 작성 중 오류가 발생했습니다.`라는 일반 alert만 보여 준다. API가 잘못된 입력을 거부하는 동작과 별개로 사용자가 수정 방법을 알 수 없는 UI 오류 처리 결함이다.

## 4. 증거와 확인 한계

- 원본 Notion에서 6개 접이식 기록의 재현 절차·Expected Result·Actual Result·스크린샷·일부 Console 정보를 읽기 전용으로 확인했다.
- 화면 증거는 사용자 내부 원본에 보존했으며 공개 저장소에는 정제되지 않은 원본 페이지나 PNG를 복제하지 않았다.
- 정확한 실행일시, 세션 소요시간, 브라우저 버전, 전체 수행 시나리오 수는 증거에서 확인하지 못해 기록하지 않았다.
- Codex가 같은 환경에서 재실행하지 않았으므로 실행 결과는 `User-reported`로 구분한다.
- TF-BUG-011의 허용 키워드 최대 길이, TF-BUG-012의 유효 모집 인원 정책, TF-BUG-013의 조회수 중복 방지 단위는 명시된 제품 정책으로 확정하지 않는다.
- Notion 화면에 포함된 Next.js `params.id` 경고는 TF-BUG-013의 조회수 +2 원인으로 단정하지 않는다.

## 5. 재검증·자동화 선정 결과

초기 후보를 다시 평가해 정상 회귀 4개와 Known Defect 2개로 분리했다. 선정 기준은 비즈니스 중요도, 기능 연결성, 반복 비용, 회귀 위험, 안정적인 자동화 가능성이다.

- 정상 회귀: 로그인, 공개 리뷰 검색, UI 리뷰 작성·결과 확인, API로 준비한 리뷰의 UI 조회·수정·삭제, 댓글 UI 등록·표시
- Known Defect: TF-BUG-010 회원가입 CTA 경로, TF-BUG-014 댓글 1자·101자 길이 안내
- TF-BUG-009: 최초 Known Defect 후보였지만 검색 대상·목적 화면·성공 결과 정책이 미정이어서 정확한 오라클을 만들 수 없어 보류. 현재 무응답을 성공으로 판정하는 테스트는 만들지 않으며 TF-BUG-010을 명확한 오라클이 있는 대체 대상으로 유지
- TF-BUG-013: 환경 제한 관찰로 후속 재검증을 보류한다. Stage 8 blocker와 자동화 성공률·대표 결함 성과에서는 제외한다.

사용자 승인으로 실행용 프런트의 별점 버튼에 접근 가능한 이름과 선택 상태만 추가해 UI 리뷰 작성·결과 확인을 자동화 범위에 포함했다. UI 댓글 수정·삭제는 댓글별 semantic container가 없어 초기 자동화에서 제외했다. CSS·순번 locator를 억지로 사용하지 않는다. TF-BUG-011의 11,177자 입력은 비용이 크고 최대 길이 정책이 없으며, TF-BUG-012는 유효 범위 정책이 미정이므로 포함하지 않았다.

## 6. 후속 처리

- 6개 결함 문서와 이 보고서의 상호 링크를 확인했다.
- Playwright 정상 회귀 5개는 수정 후 전체 실행에서 5/5 Pass했고, Known Defect 3개 실행 변형은 별도 명령에서 TF-BUG-010·014를 재현했다.
- TF-BUG-013은 환경 제한 관찰·후속 보류로 유지한다.
- 정제되지 않은 외부 원본은 공개 범위에서 제외하고 이 보고서와 개별 결함 문서를 공식 공개 산출물로 사용한다.
