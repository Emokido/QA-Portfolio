# TF-BUG-013 — 리뷰 첫 상세 조회에서 조회수가 두 번 증가함

- 결함 상태: `Open — Environment-limited reproduction`
- 발견 경로: 사용자 수동 프런트 탐색
- 기준 프로젝트: 스프린트 1 Java/Spring 완성본과 Next.js 프런트
- 기준 커밋: `e2431223ce2a18c8f944d544cba76b951ce0356d`
- 영향 기능: 리뷰 상세 조회수와 조회수 기반 표시·정렬
- 테스트 수준: Browser UI · 정적 코드 상관 분석
- 심각도: `Minor`
- 수정 우선순위: 제품 담당자 결정 필요
- 실행 주체: `User`

## 1. 요약

조회수 0인 리뷰를 처음 열면 1이 아니라 2로 증가했다. 로그인 상태와 계정을 바꾼 경우에도 첫 진입에서 2 증가하는 패턴이 관찰됐으며 이후 증가는 세션 상태에 따라 달랐다.

## 2. 원본 기록과 추적

- 수동 탐색 원본 번호: `BUG-005`
- 관련 요구사항: `TF-REQ-010` 리뷰별 조회수 관리
- 관련 위험: `TF-RISK-011` 조회수 중복 정책
- 원본 발견 기록: 사용자 내부 자료로 보존하며 공개 산출물은 아래 정제 보고서를 사용한다.
- 수동 탐색 보고서: [TripFriend 수동 프런트 탐색 보고서](../reports/manual-frontend-exploration-report.md)

## 3. 테스트 환경

- Windows 11, Chrome
- Frontend `localhost:3000`, Backend `localhost:8080`
- 로그인·로그아웃·다른 로컬 계정에서 사용자 관찰

## 4. 재현 절차

1. 커뮤니티 목록에서 조회수 0인 리뷰를 확인한다.
2. 리뷰 카드를 눌러 상세 화면에 진입한다.
3. 상세 화면과 목록의 조회수 변화를 확인한다.
4. 같은 브라우저 세션에서 다시 진입하고, 로그인 상태 또는 계정을 바꿔 비교한다.

## 5. 기대 결과

한 번의 신규 상세 조회는 코드가 정의한 세션 중복 방지 범위에서 최대 1회 증가해야 한다. 같은 세션의 동일 리뷰 재조회는 중복으로 증가하지 않아야 한다.

## 6. 실제 결과

- 비로그인 상태에서 0인 리뷰를 처음 열자 2가 됐고 같은 세션의 후속 조회에서는 증가하지 않았다.
- 로그인 상태의 첫 조회도 2 증가했으며 이후 조회에서 1씩 증가하는 경우가 있었다.
- 다른 계정의 첫 조회에서도 2 증가가 관찰됐다.

## 7. 코드 상관관계와 원인 가설

- `ReviewController.getReview`는 HttpSession의 `VIEWED_REVIEWS`에 reviewId가 처음 추가된 경우만 `isNewView=true`로 Service에 전달한다.
- `ReviewService.getReview`는 `incrementView`가 true일 때 조회수를 한 번 증가시킨다.
- 프런트 `review-detail.tsx`는 마운트 시 `getReviewById`를 호출한다.
- Next.js 개발환경에서 상세 요청이 둘 이상 발생했을 가능성은 가설이다. Network 요청 수가 확인되지 않아 확정 원인으로 기록하지 않는다.
- 화면에 함께 표시된 `params.id` 비동기 접근 경고도 조회수 중복의 직접 원인으로 단정하지 않는다.

## 8. 영향과 심각도 근거

- 조회수가 실제보다 높아지고 조회수 정렬·인기 점수의 신뢰도에 영향을 줄 수 있다.
- 리뷰 열람 자체는 가능하고 관찰 범위가 로컬 개발환경에 한정돼 `Minor`를 제안한다.

## 9. 수정 후 재검증 조건

- 상세 진입 전후 조회수와 Network의 `GET /api/reviews/{id}` 요청 횟수를 함께 기록한다.
- 로그아웃, 같은 로그인 세션, 새 세션, 다른 계정을 구분한다.
- 개발 모드와 production build에서 동일한지 비교한다.
- 같은 세션 재조회가 증가하지 않고 새 조회 단위가 정확히 1 증가하는지 확인한다.
- 조회수 높은순과 인기 점수에 중복 증가가 반영되지 않는지 확인한다.

## 10. 확인 한계

- 조회수 중복 방지의 제품 정책은 세션·회원·시간 중 하나로 명시되지 않았다. 기대 결과는 현재 Controller 코드의 세션 기준 의도에 한정한다.
- Network 요청 수, 세션 쿠키 변화와 production build 결과는 확인하지 않았다.
- Codex가 제품을 재실행하지 않았다.
